# BodyGen fidelity and VSim adaptations

Upstream is pinned in `upstream.yaml`; its Apache-2.0 licence is retained as
`LICENSE.upstream`. “Local” paths below are relative to this directory.

| Paper / pinned upstream behaviour | Local counterpart | Why it differs, and expected effect | Status | Validation |
|---|---|---|---|---|
| One unified MDP moves through five skeleton waves, one attribute wave, then control (`design_opt/envs/*`; `genesis_agent.py`) | `design.py`; `training.py` | Direct stage schedule. Design transitions are simulator-free but remain PPO transitions; only control transitions count as physics steps. | faithful | `tests/test_bodygen.py` |
| Per-current-node topology actions are applied from a snapshot; new nodes act on the next wave (`design_opt/envs/*`) | `design.py:apply_topology_actions` | Direct snapshot semantics with invalid actions as no-ops. | faithful | `tests/test_bodygen.py` |
| BodyGen edits an arbitrary MuJoCo tree | `design.py:BodyGenDesign` | Required shared-grammar adaptation. The initial body is `[1,4,6]`; root Add fills the first empty slot `1…8`; a terminal root child may be deleted; chains have at most three effectors and at least one effector remains. This exposes the complete common search space without introducing a learned slot head. | faithful adaptation | `tests/test_bodygen.py` |
| Upstream learns continuous geometry attributes with a diagonal Gaussian (`bodygen_policy.py`) | `mosat.py` categorical effector/cap heads; `design.py` attribute application | The common grammar has three effector and four cap categories rather than free MuJoCo geometry. One simultaneous absolute-selection wave chooses every active effector type and every terminal cap. Caps are passive terminal attributes. | protocol adaptation | `tests/test_bodygen.py` |
| MoSAT uses three independent Pre-LN transformer branches in the actor and three in the value model (`bodygen_policy.py`; `bodygen_critic.py`) | `mosat.py:BodyGenNetworks` | Direct PyTorch translation with six independent trunks, width 64, three blocks, one attention head, SiLU, and four-times-width feed-forward layers. | faithful | `tests/test_bodygen.py` |
| `uni_obs_norm` shares one running node-state normaliser across design/control policy and value branches (`genesis_agent.py`; `bodygen_policy.py`) | `mosat.py:RunningObservationNormalizer` owned by `BodyGenNetworks` | One checkpointed normaliser is updated from design and control node states and consumed by all six trunks. | faithful | `tests/test_bodygen.py` |
| TopoPE combines morphology topology and evolution position in a fixed 256-entry embedding (`transformer.py`) | `design.py:BodyGenDesign.topology_ids`; `mosat.py` | Root paths use stable little-endian base-nine digits: root `0`, root slot `1…8`, then child ordinal `1`. All grammar paths are collision-free, survive unrelated edits, and inherently fit the upstream 256-entry table. | faithful adaptation | `tests/test_bodygen.py` |
| Node distributions are combined into one body-transition probability (`bodygen_policy.py:get_log_prob`) | `mosat.py` stage distributions | Node log probabilities are summed for topology, categorical attributes, and control. Padding never contributes probability or entropy. | faithful | `tests/test_bodygen.py` |
| Enhanced temporal credit assignment gives design states the undiscounted remaining episode return while control uses GAE (`genesis_agent.py:estimate_advantages`) | `credit.py` | Direct translation. Termination blocks value bootstrapping, truncation retains it, and design/control return statistics remain separate. | faithful | `tests/test_bodygen.py` |
| Upstream samples complete episodes in 20 CPU workers until each exceeds `floor(50,000/20)` transitions (`genesis_agent.py:sample`) | `training.py` complete-trajectory collector | Twenty logical streams are advanced in synchronous VSim waves. Each stream finishes full trajectories until it reaches 2,500 stored unified-MDP transitions. VSim's delayed done-notification call is excluded from the MDP but charged as synchronisation waste. | simulator adaptation | `tests/test_bodygen.py`; CUDA/VSim smoke |
| Upstream reports completed training trajectories during sampling | `training.py:TrainingLogger.log_collection_rewards` | The rolling mean of complete stochastic returns is logged after every VSim collection wave on `rewards/step` and `rewards/time`. `rewards/iter` remains once per native PPO update because the policy is unchanged between waves. This changes observability only. | benchmark instrumentation | `tests/test_bodygen.py`; CUDA/VSim smoke |
| MuJoCo XML bodies are rebuilt and controlled in mujoco-py | `training.py`; `method.py` through `AntCodesignEnv` | Required VSim port. Each wave supplies its sampled typed bodies to the initial VSim construction, avoiding a redundant canonical build. Reward, termination, grammar, and physics settings are the shared benchmark task; numerical dynamics necessarily differ from MuJoCo. | simulator adaptation | CUDA/VSim train and shared-evaluator smoke |
| Upstream uses float64, 50k batches, 2,048 minibatches, ten PPO passes, actor/value Adam learning rates `5e-5`/`3e-4`, initial control log-std `-.5`, clip `.2`, gradient norm 40, gamma `.995`, and GAE lambda `.95` | `configs/benchmarks/bodygen.yaml`; `training.py` | Direct resolved defaults. Runnable and tuning YAMLs are standalone and validated before VSim starts. | faithful | `tests/test_bodygen.py` |
| Upstream samples complete trajectories but does not expose a comparison-budget audit | `training.py` counters and checkpoints | Every physical transition is charged. Total steps equal retained trajectory steps plus synchronisation waste; exact-budget tail transitions are recorded and excluded from PPO. The final checkpoint is written only at exactly `196,608,000` steps. | fidelity extension | `tests/test_bodygen.py` |
| Upstream evaluates a greedy/mean policy during training and may save a best checkpoint (`genesis_agent.py:optimize_policy`) | optional native evaluation in `training.py` | Disabled by default and uncharged. If enabled, it is diagnostic only and cannot affect training, `final.pth`, or paper checkpoint selection. | benchmark instrumentation | `tests/test_bodygen.py` |
| Upstream checkpoints policy/value weights but not a complete deterministic resume boundary | `training.py:checkpoint_state` | Expanded with all six networks, optimisers, normalisers, counters, resolved config, run identity, and Python/NumPy/Torch/CUDA RNG state. | fidelity extension | `tests/test_bodygen.py`; CUDA checkpoint-resume smoke |
| Native output is a stochastic topology-and-attribute policy paired with its shared universal controller | `method.py:BodyGenMethod` | Final evaluation draws fresh equal-weight bodies at the literal morphology seed, installs each in VSim, and uses deterministic control means plus de-normalized control-critic values. Repeated bodies remain repeated probability mass; no champion replaces the native distribution. | faithful | `tests/test_bodygen_evaluate.py`; CUDA/VSim shared-evaluator smoke |
| Upstream has no shared cross-method progress metric | `training_evaluation` in `bodygen.yaml`; shared `evaluate_return` | Optional monitoring logs `rewards/step_eval` at configured updates against charged training steps. It uses separate seeds, is not learning data, and cannot select the headline checkpoint. | benchmark instrumentation | `tests/test_bodygen.py` |

The target-machine train → checkpoint → resume → shared-evaluator CUDA/VSim
smoke and every validation row above now pass. Exact-budget, reporting-seed
paper runs produced by this implementation may therefore use the label
**faithful BodyGen**.
